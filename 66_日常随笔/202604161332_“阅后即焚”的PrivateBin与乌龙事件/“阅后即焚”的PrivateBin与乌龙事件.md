首先， `PrivateBin` 有几大特点：

* 零知识架构：服务器端完全无法访问用户数据
* 端到端加密：所有内容在浏览器中加密解密
* 自毁式分享：支持设置过期时间和访问次数限制
* 完全匿名：无需注册账户即可使用
*  可选的 “阅后即焚” 功能 



这个 `PrivateBin` 既有其他同类软件的优点，也同时具备自身的一些特点。

这个“阅后即焚”的功能相当于是一次性传递消息，保密性极高。

那么对于服务端来说，是如何搭建和设置的呢？

其实很简单，它就是跑在 `php` 引擎下的普通 `WEB` 站点。

所有配置都在 `conf.php` 这个配置文件里。

图07



都有哪些设置呢？

简单地介绍几个吧，首先是站点名称的显示，这个可以避免看错消息是从哪边发送过来的。

```
[main]
; (可选) 站点显示名称，默认"PrivateBin"
name = "网管小贾的PrivateBin"
```



通常 `PrivateBin` 是用来发送消息，比如灵活一些，但也可以开启文件传递功能，不过要注意开放站点文件上传的大小限制。

```
; 启用或禁用文件上传功能，默认为false
fileupload = true

; 每个文档或评论的大小限制（以字节为单位），默认为10兆字节
sizelimit = 10000000
```

图08



需要注意，文件上传大小仍然受到系统限制的约束。

请记住，必须同时配置 `PHP` 和 `Web` 服务器，才能上传请求的大小文件。

如有需要，可以在 `php.ini` 文件中调整参数 `upload_max_filesize` 、`post_max_size` 和 `memory_limit`（为处理接收到的数据，`memory_limit` 应设置为 `upload_max_filesize` 的两倍）。

`PrivateBin` 会在文件过大时显示错误消息，但如果文件大小超出了 `PHP` 或 `Web` 服务器配置的限制，则 `PHP` 代码无法处理，`Web` 服务器将返回通用的 `500` 错误。

以下就是请求和错误返回的大概流程样子。

```
  ┌──────────────┐
  │ POST request │
  └──────┬───────┘
         │
   ┌─────▼──────┐
   │ webserver  │
   │ POST limit ├─────────────────┐
   └─────┬──────┘      ┌──────────▼─────────────┐
         │             │ HTTP response code 500 │
   ┌─────▼───────┐     └──────────▲─────────────┘
   │ PHP request ├────────────────┘
   │    limit    │
   └─────┬───────┘
         │
   ┌─────▼──────┐
   │ PrivateBin │
   │ size limit ├──────────────────┐
   └─────┬──────┘      ┌───────────▼───────────────┐
         │             │ message "Paste is limited │
┌────────▼──────────┐  │ to %s of encrypted data." │
│ upload successful │  └───────────────────────────┘
└───────────────────┘
```



自带语言设置，选择方便。

```
; 默认情况下，PrivateBin会根据浏览器猜测访问者的语言设置。
; 您也可以选择启用语言选择菜单，该菜单使用一个会话cookie，用于在浏览器关闭之前存储用户的选择。

```
